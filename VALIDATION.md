## Whole-chord duration authoring

- Extends main `821679c` with an explicit **Apply chord duration** operation. Selecting any tone of a supported simple chord changes all tones together. Shortening inserts one rest after the final tone; lengthening consumes only the immediately following supported rest in the same voice/staff/divisions, preserving any representable remainder. Chords keep their original leader, spelling, accidental, fingering, positions, source metadata and onset.
- Existing complete-measure, untouched-written-note, playback and tempo guards remain in force. Mixed-duration/rhythm, nonadjacent, duplicate-pitch and cross-staff chords, ties, grace/cue, beams, tuplets, complex notation, unsupported attributes and stale/ambiguous mappings still fail closed. No individual-tone duration change, multiple-rest borrowing, barline crossing or automatic layout is introduced.
- Focused verification passes **186 tests across 11 authoring/UI/App files**, explicit TypeScript checking and whitespace checks. Includes **55 additional tests** for leader/middle/final selection, grow/shrink/full-rest consumption, representable 64th-note precision, rest positions, spelling/fingers/dots, namespaces, multipart/pickup/final timing, tempo changes inside held chords, provenance and repeated edits, confirmation/cancellation, immutable saved originals, real project/MusicXML round trips, pending-import invalidation and stale-tab conflicts. Existing large notation-bundle warnings remain. Independent review is pending at this record.
- These checks use original synthetic scores with simulated DOM, engraving, dialogs and downloads. No browser/device/recognition-engine run or private score is part of this slice. No dependencies, source files, stored originals, export formats or persisted schemas are changed by authoring a draft.
